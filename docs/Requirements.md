## 1. 项目定位

**GoReadwise** — 面向开发者与深度学习者的全栈知识卡片箱（Zettelkasten）系统。

核心价值主张：把"读到的东西"（网页剪藏）与"想到的东西"（原子卡片）通过 `[[双向链接]]` 编织成一张可视化的知识网络，并让这张网络在编辑的瞬间自动重构，无需人工维护索引。

**非目标（明确排除，防止范围漂移）**：
- 不做多用户 SaaS 计费/团队协作/权限矩阵
- 不做移动端原生 App
- 不做全文语义检索（向量库/Embedding）
- 不做 PDF 批注、电子书阅读器
- 不做 Obsidian 插件生态兼容

## 3. 需求矛盾与歧义裁决（Contradiction Detection）

PM 阶段检测到 6 处需求内部矛盾或未定义边界。以下为**默认裁决**，后续 Agent 不得推翻，若用户异议须在 `/auto` 之前提出。

### C-1｜前端框架二选一未定
- **矛盾**：原文写「Vue 3 / Svelte」，两者不可共存于同一 SPA。
- **裁决**：选定 **Vue 3.5 + TypeScript + Vite**。
- **理由**：Cytoscape.js 与 Vue 的生命周期集成（`onMounted` 挂载容器 + `onUnmounted` 销毁实例）模式成熟；Monaco/CodeMirror 的 Vue 封装生态更完整。Svelte 不再出现在任何交付物中。

### C-2｜「手写正则解析器」与解析正确性冲突 ⚠️ 最高技术风险
- **矛盾**：原文要求「手写或扩展正则解析器」识别 `[[卡片名称]]`。但纯正则无法感知 Markdown 上下文，会错误解析以下位置的 `[[...]]`：
  1. 围栏代码块 ` ```go ... ``` ` 内部
  2. 行内代码 `` `[[not a link]]` `` 内部
  3. 数学公式块 `$$ ... $$` 内部
  4. HTML 注释 `<!-- ... -->` 内部
  5. 转义写法 `\[[literal]]`
- **裁决**：采用**「预处理遮罩 + 正则扫描」两段式手写解析器**（仍属"手写解析器"范畴，满足原文要求）：
  - 第一段：单遍字符扫描（state machine）标记出所有代码块/行内代码/公式/注释的字节区间，生成 mask 位图；
  - 第二段：正则 `\[\[([^\[\]\|\n]+?)(\|([^\[\]\n]+?))?\]\]` 扫描全文，命中后查 mask 位图，落在遮罩区内则丢弃。
- **验收**：该解析器必须有独立单元测试，上述 5 类误判场景全部覆盖且通过。

### C-3｜链接目标是"卡片名称"而非 ID → 重命名与悬空链接未定义
- **矛盾**：`[[卡片名称]]` 按标题引用。若卡片被重命名，或引用了尚不存在的卡片，行为未定义。
- **裁决**：
  - **悬空链接（Dangling Link）合法**：`[[尚不存在的卡片]]` 保存时在关系表中记录为 `target_card_id = NULL` + `target_title = '尚不存在的卡片'`。图视图中以**虚线边 + 半透明幽灵节点**呈现，点击即以该标题创建新卡片。
  - **重命名级联**：卡片改名时，后端异步协程扫描所有 `target_title = 旧名` 的关系记录，**自动改写引用方卡片正文中的 `[[旧名]]` 为 `[[新名]]`**，并重建关系。此操作须记入操作日志。
  - **标题唯一性**：卡片标题加唯一约束（大小写不敏感、去首尾空格后比较）。创建重名卡片返回 `409 Conflict`。
  - **别名语法**：支持 `[[卡片名称|显示文本]]`，解析时以 `|` 前段为链接目标。

### C-4｜「异步协程更新图结构」导致读写一致性窗口
- **矛盾**：原文明确要求保存后**异步**重算关系。但前端右栏 Backlink 与图视图若在异步完成前读取，会看到旧数据，用户会认为是 Bug。
- **裁决**：**同步解析 + 异步扩散**的混合模型：
  - **同步事务内**完成：正文落库、当前卡片的**出边（正向引用）**全量 diff 与写入。保证保存后立刻 `GET /cards/{id}/links` 是正确的。
  - **异步协程**完成：图快照缓存重建、悬空链接补链（新卡片创建时回填此前指向它的 NULL 引用）、重命名级联改写、全图度数/聚类统计。
  - 卡片表增 `graph_version` 单调递增字段；异步任务完成后自增全局版本号，前端通过 SSE 收到 `graph:invalidated` 事件后按需刷新。
  - **幂等性**：异步任务以 `card_id + content_hash` 为幂等键，重复投递不产生重复边。

### C-5｜「多级标签」层级模型未定义
- **矛盾**：原文只说「多级标签关联」，未定义是树形实体还是路径字符串。
- **裁决**：采用 **路径式标签（Path Tag）**，如 `tech/golang/concurrency`。存储为单张 `tags` 表带 `full_path` 与 `parent_id`，写入时自动创建缺失的祖先节点。查询 `tech/golang` 时默认**包含子孙**（前缀匹配）。标签在正文中以 `#tech/golang` 语法书写，由同一解析器提取。

### C-6｜「点击节点直接开窗编辑」与三栏布局的空间冲突
- **矛盾**：三栏编辑器已占满视口，图视图中点击节点再"开窗"会产生嵌套编辑器。
- **裁决**：图视图中点击节点弹出**浮层快速编辑器（Quick Edit Modal）**，仅含标题 + Markdown 源码 + 保存/在完整编辑器中打开两个动作，**不包含**嵌套的三栏渲染与 Backlink 栏。避免状态双写。

## 7. 建议构建顺序（Phase Order Recommendation）

> 最终决策权归 Phase 1 Chief Architect，PM 在此给出强烈建议及理由。

**建议：Logic-First（交换 Phase 2 与 Phase 3）**

**理由**：本项目前端主体是 **Markdown 编辑器 + Cytoscape 图画布**，属于 SOP v13 明确列举的「editor / canvas / visualization」类型 —— 其组件结构、Props 形状、Pinia store 模型完全**派生于**双链关系表与图数据结构。若先做 UI，一旦解析引擎产出的 `LinkRef` / `GraphNode` / `GraphEdge` 结构确定，前端组件将面临大规模返工。故先落地数据模型 + 解析引擎 + 图 API，再据真实契约构建 UI。
